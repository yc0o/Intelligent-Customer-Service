# 溪谷优选 · 智能客服协同平台

面向 **访客 / 客服 / 管理员** 三类角色的在线客服系统：访客侧提供智能问答与转人工，客服侧提供排队接入、上下文接管与工作台，管理侧提供知识库、会话回溯与运营看板。

- 零第三方依赖，仅需 Node.js ≥ 22.5（使用内置 `node:sqlite` 与原生 `http`）
- 桌面端与移动端自适应，无需构建步骤
- 附带端到端冒烟测试脚本，30 项断言覆盖完整业务链路

> **上线状态**：当前版本定位为**演示 / 单机内网试用原型**，尚未达到公网生产要求。
> 部署条件评估与 P0 修复清单见 [docs/上线评估报告.md](docs/上线评估报告.md)；
> 部署拓扑、systemd / Nginx 配置与回滚步骤见 [docs/部署与回滚手册.md](docs/部署与回滚手册.md)。

```bash
npm start          # 启动，默认 http://localhost:3000
npm run verify     # 另一个终端执行，端到端验证
npm run reset      # 重置演示数据（需重启服务）
```

## 一、市面主流平台功能调研

调研对象覆盖海外以工单/会话为中心的两类代表产品（Zendesk、Intercom），以及国内在线客服厂商的通用形态（网易七鱼、智齿客服、Udesk、美洽、中通天鸿等）。

| 能力域 | 主流产品的典型做法 | 本项目取舍 |
| --- | --- | --- |
| 接入渠道 | 网页、App、公众号、小程序、邮件、电话统一进线，一个工作台接待 | **只做 Web 在线聊天**，把链路上的协同做深 |
| 智能问答 | 知识库/文档检索 + 大模型生成，回答带出处，支持多轮与追问 | 采用 **IDF 加权的中文匹配 + 置信度**，可解释、可离线运行，接口留出替换大模型的位置 |
| 人机协同 | 机器人先行，识别到复杂/敏感/情绪问题转人工，**上下文随行** | 完整实现：转人工触发组合策略 + 自动生成会话摘要 |
| 路由分配 | 技能组路由、轮询、负载均衡、VIP 优先、SLA 升级 | 实现 **在线 + 负载最低 + 最大并发** 的自动分配，附排队位次 |
| 坐席工作台 | 会话列表、客户画像、快捷回复、知识推荐、内部备注、转接 | 三栏式工作台：会话列表 / 对话 + AI 摘要 / 客户资料 + 话术助手 |
| 知识运营 | 文档导入、FAQ 抽取、相似问扩写、健康度检测 | 知识库 CRUD + 相似问法 + 关键词，附带**知识缺口**分析（低置信度提问聚类） |
| 服务质量 | CSAT/NPS、质检抽检、会话回溯、SLA 达成率 | 满意度（星级 + 标签 + 文本）、会话全量回溯、处理轨迹时间线 |
| 数据看板 | 咨询量、首响、解决率、转接率、坐席工作量、热点问题 | 6 项 KPI + 7/14/30 天趋势 + 满意度分布 + 坐席排行 + 知识缺口 |
| 权限与审计 | 角色分权、数据可见范围、操作日志 | 三角色权限矩阵 + 关键动作事件留痕 |
| 本次不做 | 全渠道、工单流转、SLA 引擎、语音、质检打分、多租户 | 与"人机协同闭环"无关，避免摊薄深度 |

**结论：对本项目最有价值的是"闭环"，而不是功能数量。**
一条会话要能完整走完 `智能应答 → 上下文追问 → 低置信度转人工 → 排队分配 → 人工接管/转接 → 结束 → 评价 → 统计 → 反哺知识库`，每一环都有状态、有归属人、有可查记录。这比堆十个孤立的页面更能体现系统设计能力。

## 二、角色与权限边界

| 能力 | 访客 | 客服 | 管理员 |
| --- | --- | --- | --- |
| 发起会话 | ✅ 仅本人 | ❌ | ❌ |
| 查看会话内容 | ✅ 仅本人会话 | ✅ 排队池 + 分配给自己的会话 | ✅ 全部（只读回溯） |
| 发送消息 | ✅ 本人会话 | ✅ 自己接待的会话 | ❌ 不参与一线接待 |
| 查看客户资料 | ✅ 仅本人基础信息 | ✅ 接待中的客户（含历史会话/评分） | ✅ 全部 |
| 接入 / 接管会话 | ❌ | ✅ 抢接排队会话 | ❌ |
| 转接会话 | ❌ | ✅ 自己的会话，可转给任意客服 | ❌ |
| 结束会话 | ✅ 本人会话 | ✅ 自己的会话 | ✅ 强制结束（异常兜底） |
| 提交满意度 | ✅ 仅本人会话 | ❌ | ❌ |
| 知识库 | ❌ 仅间接使用 | ✅ 检索用于回复 | ✅ 增删改查、启停 |
| 数据统计 | ❌ | ✅ 个人负载与今日接待 | ✅ 全平台看板 |
| 客服账号 | ❌ | ❌ | ✅ 创建、调整状态 |
| 规则配置 | ❌ | ❌ | ✅ 阈值、并发、分配开关、文案 |

设计原则：

1. **管理员不代替客服发消息**——避免"既当裁判又当运动员"，管理员的干预手段是强制结束与配置，不是接管对话。
2. **客服的数据可见范围 = 排队池 + 自己的会话**——客服能预览排队会话以决定是否接入，但看不到其他客服正在处理的会话。
3. **访客只有会话 token，没有账号体系**——降低进线门槛；所有访客接口都从 token 反查 visitor_id，不接受前端传入的会话 ID。

## 三、关键交互流程

### 1. 访客主流程

```
进入页面
  └─ 自动创建访客身份 + 会话（欢迎语）
       └─ 提问
            ├─ 意图=问候/致谢 → 直接回应
            ├─ 意图=转人工   → 进入人工队列
            ├─ 命中知识库(置信度 ≥ 阈值) → 回答 + 置信度 + 承接上文标记
            ├─ 未命中(第 1 次) → 澄清 + 推荐候选问题 + 「转人工客服」按钮
            ├─ 未命中(连续 2 次) → 自动转人工
            └─ 负面情绪且低置信度 → 优先转人工
```

### 2. 转人工与排队分配

```
转人工请求
  └─ 会话状态 waiting / mode queue，写入 transfer 事件
       ├─ 有在线客服且未达最大并发 → 立即分配（负载最低优先）
       │     └─ 会话 active / mode human，插入"客服已接入"系统消息
       └─ 无可用客服 → 返回排队位次，访客端展示等待横幅
             └─ 每 3 秒扫描队列；客服上线或结束会话后自动补位
```

### 3. 会话状态机

```
        ┌──────────── bot 应答中 ────────────┐
        │  active / bot                      │
        └──────┬───────────────────┬─────────┘
     转人工    │                   │ 访客/客服结束
               ▼                   ▼
        waiting / queue        closed（可评价）
               │                   ▲
     分配/抢接  │                   │ 结束
               ▼                   │
        active / human ────────────┘
               │
               └─ 转接：agent_id 变更，transfer_count+1，历史与摘要保留
```

### 4. 客服工作台动作

```
排队中 ──抢接──▶ 我的会话 ──回复/查话术──▶ 结束 ──▶ 访客收到评价邀请
                    └──转接──▶ 其他客服（原客服立即失去发言权限）
```

## 四、智能问答与转人工策略

**匹配算法**（`src/ai.js`，无外部依赖）：

1. 归一化：全角转半角、小写、去寒暄词（"请问/我想问/帮我"等）。
2. 分词：中文二元切分 + 单字降权（0.28）+ 英文/数字词，避免依赖词典。
3. 打分：`Σ(命中词权重 × IDF) / Σ(查询词权重 × IDF)`，得到 0–1 的覆盖率。
4. 加权：知识条目的关键词被原文包含时最多 +0.24；追问时把上一轮问题词以 0.5 权重并入查询。
5. 置信度：`score × 0.94`，并做一条"长句只命中 1 个双字词"的降权保护，避免答非所问。
6. 上下文：会话保存 `context_json`（当前话题、知识条目、最近提问、订单号），追问命中时在气泡上标"承接上文"。

**转人工触发（组合条件）**：

| 触发 | 条件 | 结果 |
| --- | --- | --- |
| 主动要求 | 命中"转人工/人工客服/真人/找人工" | 立即入队 |
| 连续未命中 | 置信度 < 阈值，连续 2 次 | 自动入队 |
| 负面情绪 | 含投诉/退钱/曝光等词，且置信度 < 0.6 | 入队并致歉 |
| 兜底提示 | 首次未命中 | 澄清 + 候选问题 + 转人工按钮 |

阈值、最大并发、自动分配开关均可在管理后台 **规则配置** 中实时调整，无需重启。

### 自动验证

服务启动后，另开终端：

```bash
npm run verify
```

脚本会真实走完：建会话 → 命中知识库 → 上下文追问 → 连续低置信度转人工 → 排队 → 客服上线自动分配 → 工作台读取客户资料/AI 摘要/推荐答案 → 客服回复 → 访客收到 → 越权校验（访客/客服/管理员三方）→ 转接 → 原客服失去权限 → 结束 → 评价 → 重复评价拦截 → 管理端统计与检索 → 新增知识即时命中。

预期输出（节选）：

```
  ✓ 机器人命中知识库并给出答案  置信度 94% · 退款多久能到账？
  ✓ 多轮上下文跟随（追问运费）  退货运费由谁承担？
  ✓ 连续低置信度自动转人工  action=queue
  ✓ 排队会话自动分配给在线客服  会话 #10 → 林小满
  ✓ 转人工时生成 AI 会话摘要  验收访客（普通会员）咨询「退货运费由谁承担？」
  ✓ 原客服失去该会话的发言权限  HTTP 403
  结果：30 通过，0 失败
```

验证会产生一条测试会话与访客记录；执行 `npm run reset` 并重启服务即可恢复干净的演示数据。

| 4 | 登录 `agent1`，查看"排队中" | 会话被自动分配；列表出现该访客；打开后顶部有 AI 摘要 |
| 5 | 客服回复消息 | 访客端 1 秒内出现人工气泡，头部变为客服姓名与"人工"标识 |
| 6 | 客服点"转接"给 agent2 | 访客端出现转接系统提示；agent1 不能再发言；agent2 打开即见完整历史 |
| 7 | 客服点"结束" | 访客端出现评价卡（5 星 + 标签 + 文本） |
| 8 | 访客提交 5 星评价 | 显示"感谢你的评价"；管理后台满意度 +1 |
| 9 | 管理后台「会话记录」搜索访客名 | 命中该会话，点"查看"可看到完整对话与处理轨迹 |
| 10 | 「知识库」新增一条并启用 | 访客再问相关问题，无需重启即可命中 |
| 11 | 「规则配置」把阈值调到 0.6 | 原本能命中的问题会转为澄清/转人工 |
| 12 | 手机宽度打开 `/`、`/agent`、`/admin` | 聊天全屏、工作台列表⇄聊天切换、后台顶部横滑导航 |

## 九、已知边界与后续扩展

**当前边界**

- 知识匹配是词面匹配，不做语义向量；同义改写（"钱什么时候退"→"退款到账"）依赖 `variants` 维护。
- 单进程内存 SSE，未做多实例广播；适合演示与单机部署。
- 访客无账号体系，换浏览器/清缓存即新身份；历史会话通过 token 绑定。
- 未做消息已读回执、附件、语音、工单流转与 SLA。

**可扩展方向**

1. 把 `src/ai.js` 的 `analyze()` 替换为向量检索或大模型（保持返回结构不变），并保留置信度门槛。
2. 分配策略插件化：技能组、VIP 优先、轮询、上次接待人优先。
3. 知识库文档导入（PDF/Word）与相似问自动扩写。
4. 会话质检：关键词命中、服务禁语、响应超时标红。
5. 多实例部署：SSE 换 Redis Pub/Sub，SQLite 换 PostgreSQL。
