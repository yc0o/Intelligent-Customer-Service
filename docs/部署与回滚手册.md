# 部署与回滚手册（草案）

> **状态：草案，暂不可直接用于生产。**
> 本手册描述的是"P0 全部关闭之后"的目标部署形态。当前代码仍缺少身份安全、优雅退出、日志与备份能力，**请先按《上线评估报告》完成 P0-1 至 P0-10 再执行本文档**。
> 文中标注 `[待 P0-x]` 的步骤依赖对应修复，当前版本尚不支持。

- 适用场景：单机内网 / 小团队试用（≤10 坐席，≤200 并发访客）
- 目标系统：Linux（Ubuntu 22.04 / Debian 12 / Rocky 9），Node.js 22.x
- 部署形态：Nginx 终止 TLS → Node 单实例 → SQLite（WAL）

## 2. 部署拓扑与端口

```
用户浏览器
   │ HTTPS 443
   ▼
┌──────────────┐   静态资源直出 / SSE 关闭缓冲 / 登录限流 / TLS 终止
│    Nginx     │
└──────┬───────┘
       │ HTTP 127.0.0.1:3000
       ▼
┌──────────────┐   systemd 守护，单实例，固定 Node 22.x
│  Node 应用   │
└──────┬───────┘
       │ 文件读写
       ▼
/var/lib/xigu/app.db  ── 每日备份 → /var/backups/xigu（保留 7 份）
```

| 项 | 值 | 说明 |
| --- | --- | --- |
| 对外端口 | 443 | 仅 Nginx 暴露 |
| 应用端口 | 3000（127.0.0.1） | 不绑定 0.0.0.0 |
| 运行用户 | `xigu`（无登录 shell） | 不要用 root |
| 代码目录 | `/opt/xigu/current` → `releases/<version>` | 软链切换实现回滚 |
| 数据目录 | `/var/lib/xigu` | 权限 `700`，独立于代码 |
| 日志 | journald + 应用 JSON 日志 | 不写本地滚动文件 |

## 3. 环境准备

### 3.1 安装 Node（锁定小版本）

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v          # 必须为 22.x，记录具体小版本到发布记录
```

> `node:sqlite` 是实验特性，**不要跨主版本升级**；升级前必须在预发跑完整回归。

### 3.2 创建用户与目录

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin xigu
sudo mkdir -p /opt/xigu/releases /var/lib/xigu /var/backups/xigu
sudo chown -R xigu:xigu /opt/xigu /var/lib/xigu /var/backups/xigu
sudo chmod 700 /var/lib/xigu
```

### 3.3 环境变量

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `PORT` | 否 | 3000 | 应用监听端口 |
| `DB_PATH` | 是 | `./data/app.db` | 生产指向 `/var/lib/xigu/app.db` |
| `NODE_ENV` | 是 | — | `production` |
| `SEED_DEMO` | 否 | — | **生产禁止设置** `[待 P0-7]` |

## 4. systemd 守护

`/etc/systemd/system/xigu.service`：

```ini
[Unit]
Description=Xigu Support Platform
After=network.target

[Service]
Type=simple
User=xigu
Group=xigu
WorkingDirectory=/opt/xigu/current
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=DB_PATH=/var/lib/xigu/app.db
ExecStart=/usr/bin/node --disable-warning=ExperimentalWarning server.js
Restart=always
RestartSec=3
KillSignal=SIGTERM
TimeoutStopSec=25
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/xigu
StandardOutput=journal
StandardError=journal
SyslogIdentifier=xigu

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now xigu
sudo systemctl status xigu
journalctl -u xigu -f
```

> `TimeoutStopSec=25` 必须大于应用的优雅退出耗时（建议应用侧 ≤20s），否则 systemd 会强杀。

## 5. Nginx 反向代理

### 5.1 限流区（必须写在 `http {}` 内）

```nginx
limit_req_zone $binary_remote_addr zone=login_zone:10m rate=10r/m;
limit_req_zone $binary_remote_addr zone=session_zone:10m rate=30r/m;
```

### 5.2 站点配置

```nginx
server {
    listen 80;
    server_name support.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name support.example.com;

    ssl_certificate     /etc/letsencrypt/live/support.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/support.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    client_max_body_size 1m;
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    location = /api/auth/login {
        limit_req zone=login_zone burst=5 nodelay;
        proxy_pass http://127.0.0.1:3000;
        include /etc/nginx/proxy_params_xigu.conf;
    }

    location = /api/visitor/session {
        limit_req zone=session_zone burst=10 nodelay;
        proxy_pass http://127.0.0.1:3000;
        include /etc/nginx/proxy_params_xigu.conf;
    }

    location ~ ^/api/(visitor/)?stream$ {
        proxy_pass http://127.0.0.1:3000;
        include /etc/nginx/proxy_params_xigu.conf;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        chunked_transfer_encoding off;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        include /etc/nginx/proxy_params_xigu.conf;
    }
}
```

`/etc/nginx/proxy_params_xigu.conf`：

```nginx
proxy_http_version 1.1;
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 60s;
proxy_connect_timeout 5s;
```

> **SSE 三个关键点**：`proxy_buffering off`（否则消息被攒着不发）、`proxy_read_timeout` 大于心跳 25s、`proxy_http_version 1.1`。
> 如果 SSE 仍然不实时，先查 `proxy_buffering`，再查是否有中间层（CDN/WAF）做了缓冲。

## 7. 发布流程

### 7.1 目录约定

```
/opt/xigu/
├── releases/
│   ├── 2026-11-20-1/
│   └── 2026-11-24-1/
└── current -> releases/2026-11-24-1
```

### 7.2 步骤

```bash
set -euo pipefail
VER=2026-11-24-1
SRC=/tmp/xigu-build            # 已通过 CI 的构建产物
DATA=/var/lib/xigu/app.db
BK=/var/backups/xigu

# 1) 备份数据库（禁止用 cp）
sqlite3 "$DATA" ".backup '$BK/pre-$VER.db'"
gzip -f "$BK/pre-$VER.db"

# 2) 备份当前配置
sqlite3 "$DATA" "select key || '=' || value from settings;" > "$BK/settings-$VER.txt"

# 3) 落代码
sudo mkdir -p /opt/xigu/releases/$VER
sudo cp -r "$SRC"/. /opt/xigu/releases/$VER/
sudo chown -R xigu:xigu /opt/xigu/releases/$VER

# 4) 切换
sudo ln -sfn /opt/xigu/releases/$VER /opt/xigu/current
sudo systemctl restart xigu

# 5) 冒烟
sleep 2
curl -fsS http://127.0.0.1:3000/api/health | grep '"ok":true'
curl -fsS -o /dev/null -w '%{http_code}\n' https://support.example.com/
node scripts/verify.js          # 预发执行，生产可跳过
```

### 7.3 发布后 10 分钟观察项

| 指标 | 期望 |
| --- | --- |
| 5xx 数量 | 0 |
| SSE 在线数 | 与发布前持平（客户端自动重连） |
| 平均首响 | 与发布前无明显差异 |
| 队列长度 | 不持续增长 |
| 进程重启次数 | 0 |

## 8. 回滚流程

### 8.1 触发条件

- 5xx 持续 > 1% 且 5 分钟内未恢复
- 登录/发消息主链路不可用
- 数据出现错误写入（如会话归属错乱）

### 8.2 代码回滚（2 分钟内）

```bash
ls -1 /opt/xigu/releases            # 找到上一个版本
sudo ln -sfn /opt/xigu/releases/2026-11-20-1 /opt/xigu/current
sudo systemctl restart xigu
curl -fsS http://127.0.0.1:3000/api/health
```

### 8.3 数据回滚（谨慎）

仅在确认数据被错误写入时执行，**会丢失备份点之后的数据**：

```bash
sudo systemctl stop xigu
sudo cp /var/lib/xigu/app.db /var/lib/xigu/app.db.broken.$(date +%s)

sudo gunzip -c /var/backups/xigu/pre-2026-11-24-1.db.gz > /var/lib/xigu/app.db
sudo rm -f /var/lib/xigu/app.db-wal /var/lib/xigu/app.db-shm
sudo chown xigu:xigu /var/lib/xigu/app.db
sudo chmod 600 /var/lib/xigu/app.db

sudo systemctl start xigu
sqlite3 /var/lib/xigu/app.db "select count(*) from conversations;"
```

> 顺序必须是"停服 → 还原 → 删 WAL → 起服"。带着旧 WAL 还原主库会造成数据错乱。

### 8.4 Schema 回滚

迁移脚本成对存在 `migrations/`：

```
migrations/
├── 001_add_session_expiry.up.sql
├── 001_add_session_expiry.down.sql
```

只允许"先 up 后 down"的成对变更；禁止直接修改线上表结构不留回滚脚本。

## 9. 备份策略

`/usr/local/bin/xigu-backup.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail
TS=$(date +%Y%m%d-%H%M)
DEST=/var/backups/xigu
sqlite3 /var/lib/xigu/app.db ".backup '$DEST/app-$TS.db'"
gzip -f "$DEST/app-$TS.db"
find "$DEST" -name 'app-*.db.gz' -mtime +7 -delete
```

```cron
# 每小时增量快照，保留 7 天
0 * * * * xigu /usr/local/bin/xigu-backup.sh >> /var/log/xigu-backup.log 2>&1
```

**必须遵守**

- 只用 `sqlite3 .backup` 或 `VACUUM INTO`；**禁止 `cp app.db`**（实测丢失 27% 会话）。
- 备份文件异地存一份（对象存储/另一台机器），否则磁盘损坏时一起没。
- 每月做一次恢复演练，记录 RTO。

| 指标 | 目标 |
| --- | --- |
| RPO | ≤ 1 小时（按小时备份） |
| RTO | ≤ 10 分钟（切版本 + 还原） |
| 保留 | 7 天 |

## 10. 监控与日志

### 10.1 必须采集

| 类型 | 内容 | 来源 |
| --- | --- | --- |
| 访问日志 | ts、reqId、method、path、status、耗时、userId | 应用（P0-8 后） |
| 错误日志 | 堆栈 + reqId + 会话 ID | 应用 |
| 业务指标 | 在线坐席、排队长度、机器人解决率、首响 | 应用 `/metrics` 或定时查询 |
| 系统指标 | CPU、内存、磁盘、进程重启 | node_exporter |

### 10.2 建议告警

| 告警 | 阈值 |
| --- | --- |
| 5xx 比例 | > 1%，持续 5 分钟 |
| P95 响应时间 | > 1s，持续 10 分钟 |
| 队列长度 | > 5 且持续 10 分钟 |
| 在线坐席 | = 0 且处于服务时段 |
| 磁盘使用率 | > 80% |
| 备份失败 | 任一次失败 |

### 10.3 常用排查命令

```bash
journalctl -u xigu --since "10 min ago" | grep -E "ERROR|fatal"
curl -s http://127.0.0.1:3000/api/health
ss -tnp | grep :3000 | wc -l          # 连接数
sqlite3 /var/lib/xigu/app.db "PRAGMA wal_checkpoint(TRUNCATE);"
```

## 11. 容量与扩容

| 指标 | 单机基线 | 说明 |
| --- | --- | --- |
| 消息吞吐 | ~70 条/秒 | 实测 30 并发下 p50 254ms |
| 并发访客 | ~200 | 受 SSE 长连接与内存限制 |
| 坐席数 | ≤10 | 分配逻辑与看板均按小团队设计 |
| 日会话 | ~1 万 | 约 24MB 存储 |
| 单库上限 | 建议 < 2GB | 超过后统计查询明显变慢 |

扩容路径（按顺序）：

1. 统计改为预聚合表，去掉全量扫消息；
2. 消息增量下发 + 分页；
3. 应用多实例前，先把 SQLite 换 PostgreSQL、SSE 换 Redis Pub/Sub；
4. 静态资源上 CDN。

**不要**在多实例下直接共享 SQLite 文件：单写者 + `database is locked` 会让写入随机失败。

## 12. 常见故障

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 消息不实时，刷新才有 | Nginx 缓冲未关闭 | 检查 SSE location 的 `proxy_buffering off` |
| SSE 每分钟断一次 | `proxy_read_timeout` 小于心跳 | 调到 3600s |
| 偶发 `database is locked` | 多进程/外部工具占用 | 确认单实例；`PRAGMA busy_timeout`；避免在线 `VACUUM` |
| 重启后数据"少了一截" | 只备份了 `app.db` | 用 `.backup`；还原时删 WAL |
| 端口占用 | 旧进程未退 | `ss -lntp \| grep 3000`，systemd 已配 `Restart` |
| 机器人对一切问题都说"没理解" | `confidence_threshold` 被写成非法值 | 查 `settings` 表并修正（P0-4 修复后不会再发生） |
| 访客建档暴涨 | 被脚本刷接口 | Nginx 限流 + 应用侧 IP 限速（P0-3） |
